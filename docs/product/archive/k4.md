## Goal
Task plans become a design skeleton instead of code written as prose, each fact lives in one document, a script catches executor drift, and the driver is the default with its agents visible in Claude Code.

## Acceptance
- AC-1 Task plan follows option B: each change entry is 1–2 lines (file, new element with name and signature, who calls whom, pattern to follow, what not to do); behaviour is given as test cases with values that are red before the change; a parameter appears only when it is a product decision or a contract between parts.
- AC-2 The plan check rejects a task plan above a size limit and returns it to the architect with the reason.
- AC-3 One source per entity: decisions, contracts and criteria are referenced by id, not copied into the task plan, the review input or the final report; the review input is self-contained and the reviewer gets no task plan path.
- AC-4 After each executor step a script checks: files changed outside the task scope without a declared reason, removed or weakened assertions, added skip/only/disabled tests. A hit counts as red: back to the executor once with the reason; still there after that, it reaches the review as a major finding.
- AC-5 The driver is on by default in new projects; the model session stays as the fallback; what blocks it as the default is settled at the start of the sprint.
- AC-6 Agents the driver and the supervisor start are visible while they work in Claude Code's own agent list (claude agents) and can be attached to, not hidden headless processes; the user sees which agent works on which sprint step outside the HTML page.

## Out of scope
- A cheaper executor model (separate, later).
- Architect effort change: stays xhigh.
- The rest of k6 (verify picks tests from changed files, review lenses from the diff, criterion → files map).
- A comparison run or benchmark: the effect is measured in practice on the next 2–3 sprints.
- Page notifications (k7).

## Decisions
- SD-1 Option B "design skeleton": the architect decides what and where, tests say how it behaves, the executor decides how to write it; rejected: A lean plan with review as the only drift guard, C architect writes the tests (user, 2026-10-22).
- SD-2 Executor model unchanged in this sprint, so the practice measurement shows the effect of the plan shape alone (user, 2026-10-22).
- SD-3 Architect stays on xhigh (user, 2026-10-22).
- SD-4 The cheapest script checks of k6 (scope, weakened or removed assertions, skips) move into this sprint; a hit goes back to the executor (user, 2026-10-22).
- SD-5 Agent visibility in Claude Code stays in this sprint even if it is the larger part (user, 2026-10-22).
