## Goal
A run works the same when its target branch lives in a worktree other than the first one: one home tree recorded per run instead of guessing from `git worktree list`; Windows paths compared in one canonical form; the destructive-command guard active only in sprint sessions; bugs 10, 11 and the UAT close fixed. Context: `roadmapa-dwmt.md` step K3, `docs/zgloszenie-2026-10-20/bugs.txt` points 1, 4, 8, 10–14, `ideas.md` §3.1, §3.4, §3.6, and the patches F-1, F-3, F-4 in `docs/zgloszenie-2026-10-20/fixes.md` that this replaces.

## Acceptance
- AC-1 `init` records the run's home tree in `run.json`: the worktree with the target branch checked out, else the calling tree. Finish, UAT, product intake and view, `completedRuns` and the live view read it from the run; `homeTreeOf` (F-1) and `targetTree` (F-3) are replaced; `mainTreeOf` remains only as the fallback for runs without the field.
- AC-2 The live writer (`live.mjs#ensureLive`, `live.js`, live settings) uses the home tree, so the live view works when the product is not in the first worktree.
- AC-3 One path canonicalisation (native realpath, long names, forward slashes, case-insensitive comparison on win32) wherever tree paths are compared; the tests that fail with a short 8.3 `TEMP` (bugs.txt point 8) pass; a test forces a short `TEMP`.
- AC-4 The result and plan header parser accepts Windows paths with backslashes inside double quotes (unknown escapes kept literally) (point 11).
- AC-5 `hooks/guard-destructive.mjs` blocks only in sessions of a dwmt run (sessions started by the driver, `launch`, or listed in a run's session ids); elsewhere it passes. `guard.scope: run | repo | always`, default `run`; the message fits the context (point 4).
- AC-6 `/dwmt:architect` starts the `expert` skill through the Skill tool instead of telling the agent to read `expert/SKILL.md`; the expert rule against project docs allows a working document on the user's explicit request outside `knowledge/` (point 10).
- AC-7 `uat record` closes the sprint in the roadmap without a manual `product sync` (point 13).
- AC-8 A regression test: a run in an extra worktree while the first worktree is on another branch goes `init → finish → uat` with no manual steps (points 1, 12, 13, 14).

## Out of scope
